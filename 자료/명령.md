### 섹션 1: 바이브 코딩이란 (what-is) [10분]

- **핵심 메시지**: 바이브 코딩 = 코드 대신, 명확한 의도와 예상 결과로 AI를 지휘하는 것
- **Hook**:
  > "바이브"면 대충 느낌만 전달하면 되는 거 아니에요? — 아닙니다. 여기서 오해하면 안 됩니다.
- **포함 요소**: 비교 테이블(전통 vs 바이브), 할일앱 만들기 비교, 사례 목록, 한계 테이블
- **주요 내용**:
  - **정의**: "코드 한 줄 한 줄 짜는 게 아니라, '이 버튼 누르면 이렇게 동작해야 해'라고 구체적으로 지시하는 방식"
  - **전통 코딩 vs 바이브 코딩 비교 테이블**:
    | 전통적인 코딩 | 바이브 코딩 |
    |---|---|
    | 사람이 직접 코드를 짠다 | AI가 코드를 짜고, 사람이 방향을 잡는다 |
    | 문법, 규칙을 외워야 한다 | 의도와 결과를 명확하게 지시한다 |
    | 오류 하나에 몇 시간 고민 | AI한테 물어보면 바로 해결책 제시 |
    | 혼자 모든 걸 알아야 한다 | AI와 대화하면서 같이 만든다 |
  - **같은 목표, 다른 접근** (할일 관리 앱):
    - 전통: 언어 선택 → 문법 공부 → 프레임워크 → 코드 작성 → 삽질... (6개월~1년)
    - 바이브: AI에게 말하기 → 기획 대화 → 코드 생성 → 피드백 → 반복 (대화할 줄 알면 시작)
  - **비개발자들이 만든 실제 사례**:
    - 업무 자동화: 뉴스 요약 슬랙 봇, 엑셀 자동 합치기
    - 웹사이트: 포트폴리오, 스터디 관리 페이지
    - 데이터: 매출 대시보드, 경쟁사 가격 모니터링
  - **바이브 코딩의 한계** (솔직한 언급):
    | 잘 되는 것 | 어려운 것 |
    |-----------|----------|
    | 개인용/소규모 도구 | 수백만 명 동시 접속 서비스 |
    | 프로토타입, MVP | 은행/병원급 보안 시스템 |
    | 반복 업무 자동화 | 게임 엔진 같은 고성능 프로그램 |
    | 간단한 웹/앱 | 기존 복잡한 시스템에 기능 추가 |
  - **비유**: 자동차를 직접 만들 줄 몰라도 운전은 할 수 있어요. AI가 차를 만들어주지만, 운전은 여러분이 해요.
- **셀프체크**: 바이브 코딩이란? / 코드를 직접 짤 줄 알아야 하나요?
- **참고 자료**: `01-바이브코딩이란.md`, `02-바이브코더가-알아야할것.md`

### 섹션 2: AI의 유능한 상사 되기 (mindset) [8분]

- **핵심 메시지**: AI는 유능한 신입사원. 뭘 만들지 모르는 건 AI가 아니라 여러분의 문제입니다.
- **Hook**:
  > "만들어줘" 한마디면 될 줄 알았는데... 왜 내가 원하는 게 안 나오죠?
- **포함 요소**: 알아야 할 것 vs 몰라도 되는 것 대비, 5단계 성장 경로, 대화법 비교(Bad vs Good)
- **주요 내용**:
  - **몰라도 되는 것 vs 알아야 하는 것**:
    | 몰라도 됨 | 알아야 함 |
    |-----------|----------|
    | 프로그래밍 언어 문법 | 뭘 만들고 싶은지 (목적) |
    | 복잡한 알고리즘 | 프로그램의 종류 (웹? 앱? 자동화?) |
    | 코드를 직접 타이핑하는 것 | AI 결과를 확인하고 피드백하는 법 |
    | function, const 같은 키워드 | "이건 로그인 기능이구나" 판독 능력 |
  - **코드 "짜기" vs "보기"의 차이**:
    - 짜는 건 AI가 하지만, 보고 판단하는 건 여러분 몫
  - **5단계 성장 경로**:
    1. 기능 요청 수준: "로그인 만들어줘" (시작점)
    2. 명세 제공 수준: "이메일+비밀번호 입력, 유효성 검사 포함"
    3. 구조 이해 수준: "프론트는 React, 백엔드는 Node.js로"
    4. **설계 대화 수준**: "아키텍처 추천해봐" → 판단 → "이렇게 해줘" ← **오늘의 목표**
    5. 고도화: 성능/보안/확장성까지 고려
  - **대화법 비교**:
    - Bad: "투두 앱 만들어줘" → AI가 뭔가 만들긴 하는데, 원하던 게 아님
    - Good: "할 일 관리 앱을 만들고 싶어. 어떤 기능들이 필요할지 같이 정리해볼까?" → 대화하면서 기획이 잡힘
  - **3가지 마인드셋**:
    1. "한 번에 안 돼도 괜찮아" — 대화하면서 고쳐나가면 됩니다
    2. "내가 방향을 잡아야 해" — AI가 다 해주는 게 아닙니다
    3. "조금씩 배워가면 돼" — 하나씩 만들다 보면 자연스럽게 알게 됩니다
- **비유**: 유능한 신입사원한테 "알아서 해"라고 하면 엉뚱한 결과. "이 고객 데이터를 이 기준으로 정리해줘"라고 하면 완벽한 결과.
- **셀프체크**: "만들어줘"와 "같이 정리해보자"의 차이는? / 5단계 중 오늘의 목표 수준은?
- **참고 자료**: `02-바이브코더가-알아야할것.md`, `03-유능한상사되기.md`

### 섹션 3: 도구 세팅 — 4가지 무기 (tools) [10분]

- **핵심 메시지**: 터미널, VS Code, Git, NPM — 이 4가지만 있으면 바이브 코딩 준비 완료
- **Hook**:
  > 터미널이라고 하면 겁부터 나시죠? 까만 화면에 깜빡이는 커서... 근데 사실 카카오톡이랑 똑같아요.
- **포함 요소**: 4대 도구 정리 테이블, 각 도구별 비유 + 설치 명령어, 설치 완료 후 확인 방법
- **주요 내용**:
  - **도구 1: Claude Code — "손발이 달린 AI"**
    - 웹 ChatGPT/Claude = "말만 하는" 조언자 (코드 복붙은 내가)
    - Claude Code = "손발이 달린" 실무자 (파일 생성/수정/실행까지 직접)
    - 설치: `npm install -g @anthropic-ai/claude-code` → `claude` 실행
    - 비유: 카카오톡(사람↔사람) vs 터미널(사람↔컴퓨터)
  - **도구 2: VS Code — "전문 주방"**
    - 3요소: 탐색기(냉장고) + 에디터(도마) + 터미널(가스레인지)
    - 핵심 명령: `code .` = "현재 폴더를 VS Code로 열어"
    - 확장: Korean Language Pack 설치
  - **도구 3: Git — "게임 세이브"**
    - Commit = 세이브 포인트 찍기
    - 3단계 주문: `git add .`(담고) → `git commit -m "메시지"`(찍고) → `git push`(밀고)
    - GitHub = 클라우드 세이브 (컴퓨터 고장나도 안전)
  - **도구 4: NPM + .env — "레시피북 + 금고"**
    - package.json = 재료 목록(레시피), `npm install` = 한번에 장보기
    - .env = 비밀번호 금고 (API 키, 비밀번호는 여기에만)
    - node_modules = 재료 보관함 (Git에 안 올림, 언제든 재설치)
  - **4대 도구 종합 테이블**:
    | 도구 | 비유 | 역할 | 핵심 명령어 |
    |------|------|------|-----------|
    | Claude Code | 손발 달린 신입 | AI 코딩 실행 | `claude` |
    | VS Code | 전문 주방 | 코드 편집 환경 | `code .` |
    | Git | 게임 세이브 | 버전 관리 | `add → commit → push` |
    | NPM | 레시피북 | 의존성 관리 | `npm install` |
- **셀프체크**: 터미널은 뭐에 비유? / Git의 3단계 주문은? / .env 파일의 역할은?

### 섹션 4: 자동화 설계 — Cron과 Webhook (automation) [7분]

- **핵심 메시지**: 반복적이고 규칙적인 데이터 처리 작업은 컴퓨터가 대신할 수 있습니다
- **Hook**:
  > "매일 아침 뉴스 검색하는 데 30분... 1년이면 180시간. 한 달치 업무 시간을 단순 반복에 버리고 있는 셈이에요."
- **포함 요소**: 자동화 3조건 테이블, Cron/Webhook 비유 설명, 뉴스 봇 구조도, AI 기획 회의 상황극
- **주요 내용**:
  - **자동화하기 좋은 일의 3가지 조건**:
    | 반복적 | 규칙적 | 데이터 처리 |
    |--------|--------|-----------|
    | 매일/매주 똑같이 하는 일 | "A면 B한다"가 명확 | 텍스트, 숫자, 파일 |
  - **자동화 가능 vs 불가능**:
    - 가능: 환율 수집, 뉴스 키워드 모으기, 정해진 보고서 발송
    - 불가능: "이 뉴스가 중요한가?" (판단), "트렌드에 맞나?" (감각)
  - **핵심 도구 2가지**:
    - **Cron(크론) = 알람 시계**: "매일 아침 9시에 이 코드 실행해"
    - **Webhook(웹훅) = 초인종**: "뉴스 나왔어!" → 슬랙으로 배달
    - API는 내가 달라고 해야 주는 것, Webhook은 알아서 던져주는 것
  - **오늘 만들 것: 뉴스 요약 슬랙 봇 구조도**:
    ```
    [Cron]        [RSS]       [AI]        [Webhook]     [Slack]
    매일 09:00 → 뉴스 수집 → 3줄 요약 → 슬랙 전송 → 폰에서 확인
    깨워줘!      데이터 가져옴  요약해줘     쏴줘!         슥 읽기
    ```
  - **AI와 기획 회의 (상황극)**:
    - 나: "뉴스 검색 자동화하고 싶어. 매일 아침 9시에 'AI' 뉴스 모아서 슬랙으로 받고 싶어."
    - AI: "GitHub Actions Cron(무료) + 구글 뉴스 RSS + 슬랙 Webhook 조합 추천해요!"
    - 나: "제목만 보내면 안 읽을 것 같아. 3줄 요약 붙여줘."
    - AI: "뉴스 수집 → AI 요약 → 슬랙 전송 순서로 짤게요!"
- **비유**: Cron = 매일 7시에 울리는 알람, Webhook = 택배 오면 울리는 초인종
- **셀프체크**: 매일 환율 수집 → 자동화 가능? / "주문 들어오면 알림" → 어떤 기술? / Cron과 Webhook의 차이는?
- **참고 자료**: `08-자동화-아이디어.md`

### 섹션 5: 실전 — 뉴스 요약 슬랙 봇 만들기 (hands-on) [15분]

- **핵심 메시지**: 수집 → 전송 → 자동화. 이 3단계를 직접 만들어봅니다
- **Hook**:
  > 지금부터 여러분의 첫 자동화 비서를 만듭니다. 컴퓨터가 꺼져 있어도 매일 아침 뉴스가 배달됩니다.
- **포함 요소**: 3단계 진행 플로우, 핵심 코드 블록(최소화+주석), 구조 다이어그램, 실행 결과 예시
- **주요 내용**:

  **[STEP 1] 데이터 수집 — RSS로 뉴스 긁어오기**
  - 크롤링("도둑") vs RSS("전단지"): RSS가 안전하고 합법적
  - 파싱(Parsing) = 생선 가시 발라내기 (필요한 정보만 추출)
  - 프로젝트 세팅:
    ```bash
    mkdir my-news-bot && cd my-news-bot
    npm init -y
    npm install rss-parser
    ```
  - AI에게 요청: "rss-parser로 구글 뉴스 RSS에서 최신 3개 기사 제목/링크 출력해줘"
  - 실행: `node index.js` → 콘솔에 뉴스 제목 출력 확인

  **[STEP 2] 슬랙 전송 — Webhook으로 메시지 쏘기**
  - 슬랙 앱 생성 → Incoming Webhook 활성화 → URL 발급
  - Webhook URL = "비밀 우체통 주소" (노출되면 안 됨 → .env에 보관)
  - 설치: `npm install axios dotenv`
  - AI에게 요청: "axios로 슬랙 웹훅에 POST 요청 보내는 코드 짜줘. 주소는 .env에서 가져와"
  - 핵심 코드 (하이라이트):
    ```javascript
    // .env에서 비밀 주소 가져오기
    const url = process.env.SLACK_WEBHOOK_URL;
    // 슬랙으로 메시지 쏘기
    await axios.post(url, { text: message });
    ```
  - 실행: `node index.js` → 슬랙 채널에 메시지 도착 확인

  **[STEP 3] 정기 실행 — GitHub Actions로 24/7 자동화**
  - GitHub Actions = "깃허브가 빌려주는 무료 컴퓨터"
  - 내 컴퓨터 꺼져 있어도 자동 실행 (서버리스 자동화)
  - 시간 주의: UTC 기준 (한국 9시 = UTC 0시 → `cron: '0 0 * * *'`)
  - 비밀값 등록: GitHub Settings → Secrets → `SLACK_WEBHOOK_URL` 추가
  - 배포: `git add . → git commit → git push` → Actions 탭에서 초록색 체크 확인
  - 완성:
    ```
    컴퓨터 꺼져 있어도 → GitHub 컴퓨터가 대신 실행
    매일 아침 9시 → 뉴스 수집 → 요약 → 슬랙 배달
    ```

- **비유**: RSS=전단지 수거, Webhook URL=비밀 우체통, GitHub Actions=24시간 일하는 대리인
- **셀프체크**: RSS와 크롤링의 차이는? / .env에 웹훅 주소를 넣는 이유는? / GitHub Actions를 쓰면 내 컴퓨터를 켜둬야 하나요?
- **참고 자료**: `09-데이터-수집정리.md`, `10-슬랙봇-만들기.md`, `11-정기실행-GitHub-Actions.md`
