## 0. 개요: 왜 바이브 코딩인가

> "AI한테 시키면 뭔가 나오긴 해요. 근데 거기서 끝이에요."
> 기능 하나 추가하려니까 꼬이고, 에러 나면 뭐가 문제인지 모르겠고, 결국 반쯤 만들다 포기하게 되죠?

**코드를 짜는 시대에서, AI를 지휘하는 시대로 바뀌었어요.**

### AI 코딩의 발전 과정

| 시기 | 수준 | 한계 |
|------|------|------|
| 2020년 이전 | "if문 예제 알려줘" → 코드 조각만 | 조립은 직접 |
| 2022년 (ChatGPT) | "로그인 기능 만들어줘" → 코드 덩어리 | 복붙/파일관리 직접 |
| 2024년~현재 | "앱 만들어줘" → 프로젝트 전체 생성 | 지휘하는 법을 알아야 함 |

**그래서 바이브 코딩이 필요해요.**

### 오늘의 흐름
💡 개념 → 🧠 마인드셋 → 🔧 도구 → ⚙️ 자동화 → 🚀 실전 → 📋 정리

## 1. 바이브 코딩이란

> "바이브"면 대충 느낌만 전달하면 되는 거 아니에요? — 아닙니다.

### 정의
코드 한 줄 한 줄 짜는 게 아니라, **"이 버튼 누르면 이렇게 동작해야 해"**라고 구체적으로 지시하는 방식이에요.

### 전통 코딩 vs 바이브 코딩

| 전통적인 코딩 | 바이브 코딩 |
|---|---|
| 사람이 직접 코드를 짠다 | AI가 코드를 짜고, 사람이 방향을 잡는다 |
| 문법, 규칙을 외워야 한다 | 의도와 결과를 명확하게 지시한다 |
| 오류 하나에 몇 시간 고민 | AI한테 물어보면 바로 해결책 제시 |
| 혼자 모든 걸 알아야 한다 | AI와 대화하면서 같이 만든다 |

### 같은 목표, 다른 접근 (할일 관리 앱)
- **전통**: 언어 선택 → 문법 공부 → 프레임워크 → 코드 작성 → 삽질... (6개월~1년)
- **바이브**: AI에게 말하기 → 기획 대화 → 코드 생성 → 피드백 → 반복 (대화할 줄 알면 시작)

### 비개발자들이 만든 실제 사례
- 업무 자동화: 뉴스 요약 슬랙 봇, 엑셀 자동 합치기
- 웹사이트: 포트폴리오, 스터디 관리 페이지
- 데이터: 매출 대시보드, 경쟁사 가격 모니터링

### 바이브 코딩의 한계

| 잘 되는 것 | 어려운 것 |
|-----------|----------|
| 개인용/소규모 도구 | 수백만 명 동시 접속 서비스 |
| 프로토타입, MVP | 은행/병원급 보안 시스템 |
| 반복 업무 자동화 | 게임 엔진 같은 고성능 프로그램 |
| 간단한 웹/앱 | 기존 복잡한 시스템에 기능 추가 |

> 자동차를 직접 만들 줄 몰라도 운전은 할 수 있어요. AI가 차를 만들어주지만, **운전은 여러분이 해요.**

## 2. AI의 유능한 상사 되기

> "만들어줘" 한마디면 될 줄 알았는데... 왜 내가 원하는 게 안 나오죠?

**AI는 유능한 신입사원이에요.** 뭘 만들지 모르는 건 AI가 아니라 여러분의 문제예요.

### 몰라도 되는 것 vs 알아야 하는 것

| 몰라도 됨 | 알아야 함 |
|-----------|----------|
| 프로그래밍 언어 문법 | 뭘 만들고 싶은지 (목적) |
| 복잡한 알고리즘 | 프로그램의 종류 (웹? 앱? 자동화?) |
| 코드를 직접 타이핑하는 것 | AI 결과를 확인하고 피드백하는 법 |
| function, const 같은 키워드 | "이건 로그인 기능이구나" 판독 능력 |

### 5단계 성장 경로
1. **기능 요청 수준**: "로그인 만들어줘" (시작점)
2. **명세 제공 수준**: "이메일+비밀번호 입력, 유효성 검사 포함"
3. **구조 이해 수준**: "프론트는 React, 백엔드는 Node.js로"
4. **설계 대화 수준** ← 오늘의 목표: "아키텍처 추천해봐" → 판단 → "이렇게 해줘"
5. **고도화**: 성능/보안/확장성까지 고려

### 대화법 비교
- **Bad**: "투두 앱 만들어줘" → 원하던 게 아님
- **Good**: "할 일 관리 앱을 만들고 싶어. 어떤 기능들이 필요할지 같이 정리해볼까?" → 기획이 잡힘

### 3가지 마인드셋
1. 🔄 "한 번에 안 돼도 괜찮아" — 대화하면서 고쳐나가면 돼요
2. 🧭 "내가 방향을 잡아야 해" — AI가 다 해주는 게 아니에요
3. 🌱 "조금씩 배워가면 돼" — 하나씩 만들다 보면 자연스럽게 알게 돼요

> 유능한 신입사원한테 "알아서 해"라고 하면 엉뚱한 결과. **"이 고객 데이터를 이 기준으로 정리해줘"**라고 하면 완벽한 결과.

## 3. 도구 세팅: 4가지 무기

> 터미널이라고 하면 겁부터 나시죠? 까만 화면에 깜빡이는 커서... 근데 사실 카카오톡이랑 똑같아요.

### 도구 1: 🤖 Claude Code — "손발이 달린 AI"
- 웹 ChatGPT = "말만 하는" 조언자
- Claude Code = "손발이 달린" 실무자 (파일 생성/수정/실행까지 직접)
- 설치: `npm install -g @anthropic-ai/claude-code` → `claude`
- 비유: 카카오톡(사람↔사람) vs 터미널(사람↔컴퓨터)

### 도구 2: 💻 VS Code — "전문 주방"
- 3요소: 탐색기(냉장고) + 에디터(도마) + 터미널(가스레인지)
- 핵심 명령: `code .` = "현재 폴더를 VS Code로 열어"

### 도구 3: 💾 Git — "게임 세이브"
- Commit = 세이브 포인트 찍기
- 3단계 주문: `git add .`(담고) → `git commit -m "메시지"`(찍고) → `git push`(밀고)
- GitHub = 클라우드 세이브

### 도구 4: 📦 NPM + .env — "레시피북 + 금고"
- package.json = 재료 목록, `npm install` = 한번에 장보기
- .env = 비밀번호 금고 (API 키, 비밀번호는 여기에만)

### 4대 도구 종합

| 도구 | 비유 | 역할 | 핵심 명령어 |
|------|------|------|-----------|
| Claude Code | 손발 달린 신입 | AI 코딩 실행 | `claude` |
| VS Code | 전문 주방 | 코드 편집 환경 | `code .` |
| Git | 게임 세이브 | 버전 관리 | `add → commit → push` |
| NPM | 레시피북 | 의존성 관리 | `npm install` |

## 4. 자동화 설계: Cron과 Webhook

> "매일 아침 뉴스 검색하는 데 30분... 1년이면 180시간."

### 자동화하기 좋은 일의 3가지 조건

| 반복적 | 규칙적 | 데이터 처리 |
|--------|--------|-----------|
| 매일/매주 똑같이 하는 일 | "A면 B한다"가 명확 | 텍스트, 숫자, 파일 |

### 핵심 도구 2가지
- **⏰ Cron = 알람 시계**: "매일 아침 9시에 이 코드 실행해"
- **🔔 Webhook = 초인종**: "뉴스 나왔어!" → 슬랙으로 배달

### 뉴스 요약 슬랙 봇 구조
```
[Cron] → [RSS] → [AI] → [Webhook] → [Slack]
매일 09:00  뉴스 수집  3줄 요약  슬랙 전송  폰에서 확인
```

### AI와 기획 회의 (상황극)
- 나: "뉴스 검색 자동화하고 싶어. 매일 아침 9시에 'AI' 뉴스 모아서 슬랙으로 받고 싶어."
- AI: "GitHub Actions Cron(무료) + 구글 뉴스 RSS + 슬랙 Webhook 조합 추천해요!"
- 나: "제목만 보내면 안 읽을 것 같아. 3줄 요약 붙여줘."
- AI: "뉴스 수집 → AI 요약 → 슬랙 전송 순서로 짤게요!"

## 5. 실전: 뉴스 요약 슬랙 봇 만들기

> 지금부터 여러분의 첫 자동화 비서를 만들어요.

### STEP 1: 데이터 수집 — RSS로 뉴스 긁어오기

크롤링("도둑") vs RSS("전단지"): RSS가 안전하고 합법적

```bash
mkdir my-news-bot && cd my-news-bot
npm init -y
npm install rss-parser
```

AI에게: "rss-parser로 구글 뉴스 RSS에서 최신 3개 기사 제목/링크 출력해줘"

### STEP 2: 슬랙 전송 — Webhook으로 메시지 쏘기

Webhook URL = "비밀 우체통 주소" → .env에 보관

```bash
npm install axios dotenv
```

```javascript
// .env에서 비밀 주소 가져오기
const url = process.env.SLACK_WEBHOOK_URL;
// 슬랙으로 메시지 쏘기
await axios.post(url, { text: message });
```

### STEP 3: 정기 실행 — GitHub Actions로 24/7 자동화

GitHub Actions = "깃허브가 빌려주는 무료 컴퓨터"

시간 주의: UTC 기준 (한국 9시 = UTC 0시 → `cron: '0 0 * * *'`)

```bash
git add .
git commit -m "뉴스 봇 완성"
git push
```

완성:
```
컴퓨터 꺼져 있어도 → GitHub 컴퓨터가 대신 실행
매일 아침 9시 → 뉴스 수집 → 요약 → 슬랙 배달
```

**셀프체크:** RSS와 크롤링의 차이는? / .env에 웹훅 주소를 넣는 이유는? / GitHub Actions를 쓰면 내 컴퓨터를 켜둬야 하나요?

| 섹션 | 한 줄 요약 |

3. AI는 유능한 신입사원 — 좋은 상사가 되세요
4. 도구 4가지: Claude Code, VS Code, Git, NPM
5. 자동화의 핵심: Cron(언제) + Webhook(어디로)
