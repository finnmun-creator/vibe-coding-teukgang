### 섹션 0: 개요 — 왜 바이브 코딩인가 (overview) [5분]

- **핵심 메시지**: 코드를 짜는 시대에서, AI를 지휘하는 시대로 바뀌었습니다
- **Hook**:
  > "AI한테 시키면 뭔가 나오긴 해요. 근데 거기서 끝이에요."
  > 기능 하나 추가하려니까 꼬이고, 에러 나면 뭐가 문제인지 모르겠고, 결국 반쯤 만들다 포기하게 되죠?
- **포함 요소**: 학습 달성 목표, Hook 인용문, **"세상이 바뀌고 있어요" 시대 맥락 카드**, 도메인 전문성 인사이트, AI 코딩 발전 타임라인, 오늘의 흐름도, 다음 섹션 예고
- **주요 내용**:
  - **"세상이 바뀌고 있어요"** (시대적 맥락 — 출처: 개요보강.md 프롤로그):
    - 마이크로 서비스의 폭발: "이 기능 하나만 잘하면 돼" → AI로 빠르게 출시
    - 가격 경쟁의 시작: 개발팀 10명 → 1~2명. 인건비 절감 → 가격 파괴
    - 소규모 팀의 강세: 대기업 의사결정 3개월, 소규모 팀은 3일
    - "이건 먼 미래 얘기가 아니에요. 지금 일어나고 있어요."
  - AI 코딩의 발전 과정 (3단계 타임라인):
    | 시기 | 수준 | 한계 |
    |------|------|------|
    | 2020년 이전 | "if문 예제 알려줘" → 코드 조각만 | 조립은 직접 |
    | 2022년 (ChatGPT) | "로그인 기능 만들어줘" → 코드 덩어리 | 복붙/파일관리 직접 |
    | 2024년~현재 (Claude Code) | "앱 만들어줘" → 프로젝트 전체 생성 | 지휘하는 법을 알아야 함 |
  - **"처음엔 되는데, 기능 추가하면 꼬이고, 결국 포기하게 되죠"** 내러티브 보강:
    - 처음에 AI한테 시키면 뭔가 그럴듯한 게 나와요. "오, 진짜 되네?"
    - 그래서 신나서 기능을 하나 더 추가해요. "여기에 로그인도 붙여줘"
    - 그런데 갑자기 아까 되던 게 안 돼요. 에러가 줄줄 나와요.
    - 에러 메시지를 봐도 뭔 말인지 모르겠고, 어디를 고쳐야 하는지도 모르겠어요.
    - 결국 "에이, 그냥 처음부터 다시 하자" → 3번째 반복하면... 포기.
    - **이건 AI가 무능해서가 아니에요. 시키는 방법을 몰라서예요.**
  - **"결국 차이는 '명령하는 사람'"** (출처: `01-바이브코딩이란.md`):
    - AI 성능은 다 똑같아요. ChatGPT든 Claude든, 모델 자체의 능력은 이제 다 비슷해요.
    - 같은 AI를 써도 어떤 사람은 완성하고, 어떤 사람은 포기해요.
    - 차이는 "어떻게 시키느냐"예요.
    - 이 특강은 그 **"어떻게 시키느냐"**를 알려드려요.
  - "그래서 바이브 코딩이 필요합니다"
  - 오늘의 흐름: 개념 → 마인드셋 → 도구 → 실전 → 정리
  - **학습 달성 목표** (섹션 상단):
    - 바이브 코딩이 뭔지 자신있게 설명할 수 있어요
    - Claude Code, VS Code, Git을 직접 설치하고 사용할 수 있어요
    - AI와 대화해서 뉴스 요약 슬랙 봇을 처음부터 끝까지 만들 수 있어요
  - **도메인 전문성 인사이트**: "우리 서비스는 7일 이내만 환불 가능 — AI는 이걸 모릅니다. AI 시대의 경쟁력은 업무/비즈니스 이해도"
  - **다음 섹션 예고**: "그럼 바이브 코딩이 정확히 뭔지 알아볼게요"

### 섹션 1: 바이브 코딩이란 (what-is) [10분]

- **핵심 메시지**: 바이브 코딩 = 코드 대신, 명확한 의도와 예상 결과로 AI를 지휘하는 것
- **Hook**:
  > "바이브"면 대충 느낌만 전달하면 되는 거 아니에요? — 아닙니다. 여기서 오해하면 안 됩니다.
- **리캡**: "개요에서 AI 코딩 시대가 왔다는 걸 봤어요. 정확히 '바이브 코딩'이 뭘까요?"
- **포함 요소**: 비교 테이블(전통 vs 바이브), 할일앱 만들기 비교, 사례 목록, 한계 테이블
- **주요 내용**:
  - **정의**: "코드 한 줄 한 줄 짜는 게 아니라, '이 버튼 누르면 이렇게 동작해야 해'라고 구체적으로 지시하는 방식"
  - **MVP(Minimum Viable Product)**: 최소 기능 제품. 핵심 기능만 있는 버전을 빨리 만들어서 반응을 보는 것. 바이브 코딩은 이 MVP를 빠르게 만드는 데 특히 강해요. (출처: `01-바이브코딩이란.md`)
  - **"바이브 코딩 ≠ 대충 말하기"** (출처: `01-바이브코딩이란.md`):
    - "바이브"라는 단어 때문에 헷갈릴 수 있어요
    - "느낌만 전달하면 AI가 알아서 해주겠지?" → 이게 안 돼서 다들 막히는 거예요
    - 바이브 코딩의 진짜 의미:
      - 코드 문법은 몰라도 돼요
      - 대신 **뭘 만들지**, **왜 만들지**, **어떻게 동작해야 하는지**는 명확히 알아야 해요
      - AI한테 기술적인 지침을 정확하게 전달하는 게 핵심이에요
  - **전통 코딩 vs 바이브 코딩 비교 테이블**:
    | 전통적인 코딩 | 바이브 코딩 |
    |---|---|
    | 사람이 직접 코드를 짠다 | AI가 코드를 짜고, 사람이 방향을 잡는다 |
    | 문법, 규칙을 외워야 한다 | 의도와 결과를 명확하게 지시한다 |
    | 오류 하나에 몇 시간 고민 | AI한테 물어보면 바로 해결책 제시 |
    | 혼자 모든 걸 알아야 한다 | AI와 대화하면서 같이 만든다 |
  - **같은 목표, 다른 접근** (할일 관리 앱 — 출처: 개요보강.md lines 404-425):
    - 전통: 프로그래밍 언어 선택(JS? Python?) → 문법 공부(변수, 함수, 조건문) → 프레임워크 학습(React? Vue?) → 코드 작성 → 에러 → 구글 검색 → 삽질 → **6개월~1년** 후 겨우 간단한 앱 하나
    - 바이브: AI에게 말하기("할 일 관리 앱 만들고 싶어") → AI가 물어봄("어떤 기능이 필요해요?") → 대화하며 기획 → AI가 코드 작성 → 피드백("버튼이 너무 작아. 더 크게") → **대화할 줄 알면** 바로 시작 가능
  - **비개발자들이 만든 실제 사례** (모달 팝업으로 상세 보기 제공):
    | # | 이름 | 만든 사람 | 도구 | 한줄 설명 | URL |

    | 1 | LinkStash | 디자이너 (코딩 무경험) | Cursor | AI 스마트 북마크, 3일 만에 출시 | linkstash.vercel.app |
    | 2 | Social Archiver | 비개발자 (임형균) | 바이브코딩 | SNS 아카이빙 옵시디언 플러그인, 48개국 사용 | GitHub |
    | 3 | BLight | PM/디자이너 | Lovable | 28일 다이어트 관리 앱, 2일 만에 앱스토어 출시 | App Store |

  - **바이브 코딩의 한계** (솔직한 언급):
    | 잘 되는 것 | 어려운 것 |
    |-----------|----------|
    | 개인용/소규모 도구 | 수백만 명 동시 접속 서비스 |
    | 프로토타입, MVP | 은행/병원급 보안 시스템 |
    | 반복 업무 자동화 | 게임 엔진 같은 고성능 프로그램 |
    | 간단한 웹/앱 | 기존 복잡한 시스템에 기능 추가 |
  - **"바이브 코딩의 핵심은 대화"** (출처: `01-바이브코딩이란.md`):
    - 말하기 → 확인 → 피드백 → 반복
    - 한 번에 완성품이 나오지 않아요. 대화하면서 만들어가는 거예요.
    - AI한테 한 번 시켜서 끝나는 게 아니라, "이건 좋고, 저건 고쳐줘"를 반복하는 과정이에요.
  - **"바이브 코딩을 하다 보면"** — 성장 내러티브 (출처: `01-바이브코딩이란.md`):
    - 처음엔 AI가 뭘 하는지 하나도 몰라요. 화면에 뭔가 막 지나가는데 무슨 말인지 모르겠어요.
    - 몇 번 하다 보면 "아, 지금 로그인 부분 고치고 있구나" "여기서 에러 난 건 이것 때문이겠네" 하고 알게 돼요.
    - 코드를 짤 줄은 몰라도, **볼 줄은 알게 돼요**. 이게 성장이에요.
  - **운전 비유** (구체적 매핑 — 출처: 개요보강.md lines 446-455):
    - 자동차를 직접 만들 줄 몰라도 운전은 할 수 있어요. 근데 운전하려면 적어도 이건 알아야 해요:
    - **엑셀이 뭐고 브레이크가 뭔지** → 기본 개념
    - **신호등이 뭘 의미하는지** → 에러/경고 읽기
    - **어디로 가고 싶은지** → 만들 목표
    - AI가 차를 만들어주지만, **운전은 여러분이 해요.**
- **셀프체크**:
  - 바이브 코딩에서 사람의 역할은? → 방향 설정 + AI 결과 확인/피드백
  - "투두 앱 만들어줘"는 좋은 지시일까? → 아니요, "같이 기획해보자"가 좋은 시작
  - 바이브 코딩으로 만들기 어려운 것은? → 대규모 동시접속, 은행급 보안 시스템

### 섹션 2: AI의 유능한 상사 되기 (mindset) [8분]

- **핵심 메시지**: AI는 유능한 신입사원. 뭘 만들지 모르는 건 AI가 아니라 여러분의 문제입니다.
- **Hook**:
  > "만들어줘" 한마디면 될 줄 알았는데... 왜 내가 원하는 게 안 나오죠?
- **리캡**: "바이브 코딩이 '명확한 의도로 AI를 지휘하는 것'이란 걸 배웠어요. 어떻게 지휘해야 할까요?"
- **포함 요소**: 알아야 할 것 vs 몰라도 되는 것 대비, **"알아서 해줘" 함정**, **한 입 크기 프레임워크**, 5단계 성장 경로, **대화법 3단계 비교**, **유능한 매니저 3가지 조건**, **AI 구조적 한계 3가지**, **"잘했겠지" 전제의 위험**
- **주요 내용**:
  - **몰라도 되는 것 vs 알아야 하는 것**:
    | 몰라도 됨 | 알아야 함 |
    |-----------|----------|
    | 프로그래밍 언어 문법 | 뭘 만들고 싶은지 (목적) |
    | 복잡한 알고리즘 | 프로그램의 종류 (웹? 앱? 자동화?) |
    | 코드를 직접 타이핑하는 것 | AI 결과를 확인하고 피드백하는 법 |
    | function, const 같은 키워드 | "이건 로그인 기능이구나" 판독 능력 |
  - **"알아서 해줘"의 함정** (출처: 개요보강.md lines 126-144):
    - "할 일 추가, 삭제, 완료 체크. 스마트폰에서 돌아가게" — 이 정도면 구체적인 거 아냐? → 아니에요. 이것도 "알아서 해줘"예요.
    - AI는 이런 걸 모름: "할 일 추가" 버튼이 **어디에** 있어야 하는지, 완료 체크하면 **바로** 내려가야 하는지, 뒤로 가기 누르면 **어디로** 가야 하는지
    - 기능 목록을 줘도, **"사용자 경험"은 AI가 알아서 못 만들어요.**
  - **진짜 구체적 지시 = 한 입 크기로** (출처: 개요보강.md lines 145-161):
    1. **기획 문서 먼저**: "이 앱이 뭔지, 누가 쓰는지, 핵심 기능이 뭔지" — AI한테 같이 정리하자고 해도 OK
    2. **기능 하나씩 지시**: "먼저 할 일 추가 버튼만 만들어줘" → 확인하고, 피드백하고, 다음으로
    3. **바로바로 피드백**: "버튼 위치가 애매한데, 오른쪽 아래로 옮겨줘" → 고치고, 확인하고, 다음으로
  - **"개념이 필요한 두 가지 이유"** (출처: `02-바이브코더가-알아야할것.md`):
    1. **명확한 지시**: "알아서 해줘"가 아니라, 구체적인 주문서가 돼요. 개념을 알아야 "이건 이렇게, 저건 저렇게"라고 정확히 시킬 수 있어요.
    2. **AI 결과 판단**: AI가 만들어준 결과물을 평가할 수 있어야 해요. "이게 맞는 건가?" "뭔가 빠진 건 아닌가?" 이걸 판단하려면 기본 개념이 있어야 해요.
  - **알아야 할 구체적 개념 리스트** (출처: `02-바이브코더가-알아야할것.md`):
    - **프론트엔드/백엔드**: 화면에 보이는 부분(프론트) vs 뒤에서 돌아가는 부분(백엔드)
    - **데이터베이스**: 정보를 저장하는 곳 (엑셀 시트 같은 것)
    - **API**: 프로그램끼리 대화하는 통로 (식당 주문서 같은 것)
    - **폴더 구조**: 파일을 어떻게 정리할 것인가
    - **데이터 흐름**: 정보가 어디서 와서 어디로 가는가
  - **학습 순서** (출처: `02-바이브코더가-알아야할것.md`):
    프로그램 종류 → 구조 → 설계 개념 → 도구 → 실전
  - **코드 "짜기" vs "보기"의 차이**:
    - 짜는 건 AI가 하지만, 보고 판단하는 건 여러분 몫
  - **5단계 성장 경로**:
    1. 기능 요청 수준: "로그인 만들어줘" (시작점)
    2. 명세 제공 수준: "이메일+비밀번호 입력, 유효성 검사 포함"
    3. 구조 이해 수준: "프론트는 React, 백엔드는 Node.js로"
    4. **설계 대화 수준**: "아키텍처 추천해봐" → 판단 → "이렇게 해줘" ← **오늘의 목표**
    5. 고도화: 성능/보안/확장성까지 고려
  - **"기술적 지시가 가능한 매니저의 특징" 5가지** (출처: `03-유능한상사되기.md`):
    1. AI에게 여러 선택지를 물어볼 수 있어요 ("로그인 방식 3가지 알려줘")
    2. 선택지를 듣고 자신의 상황에 맞게 판단할 수 있어요 ("우리는 소셜 로그인이 맞겠다")
    3. 판단한 방향으로 구체적으로 지시할 수 있어요 ("구글 로그인부터 붙여줘")
    4. AI 결과물이 맞는지 확인하고 검증할 수 있어요 ("로그인 버튼 누르니까 에러 나는데?")
    5. **코드를 직접 타이핑하지 않고, 버그를 직접 수정하지 않아요** — 대신 정확히 지시해요
  - **대화법 3단계 비교** — 상품 검색/필터링 기능 (출처: 개요보강.md lines 857-922):
    - 수준 1 (막연): "상품 검색 기능 만들어줘" → 검색창만 있고 필터 없음. 필터 추가하니 기존 검색 망가짐.
    - 수준 2 (구체): "검색창 + 카테고리 필터(의류/전자/식품) + 가격대 필터(1만 이하/1~5만/5만 이상)" → 기능은 나옴. 근데 상품 1000개 넘으면 느려짐.
    - 수준 3 (기술적 — 목표): "상품 검색/필터 만들 건데, 방식 먼저 정하자. 상품 많아질 수 있어서 성능도 고려" → 방식의 장단점을 듣고 내가 판단. 구조를 이해하고 있어서 문제 생기면 어디를 고칠지 앎.
  - **유능한 매니저의 3가지 조건** (출처: 개요보강.md lines 252-267):
    | 조건 | 구체적으로 |
    |------|-----------|
    | 뭘 만들지 명확히 하기 | "이런 사람이 이렇게 쓸 앱이야" — 기획 문서로 정리 |
    | 한 입 크기로 나누기 | "먼저 이 화면만 만들어줘" — 한 번에 하나씩 |
    | 바로바로 피드백하기 | "여기 이렇게 고쳐줘" → 확인 → 다음 |
  - **3가지 마인드셋**:
    1. "한 번에 안 돼도 괜찮아" — 대화하면서 고쳐나가면 됩니다
    2. "내가 방향을 잡아야 해" — AI가 다 해주는 게 아닙니다
    3. "조금씩 배워가면 돼" — 하나씩 만들다 보면 자연스럽게 알게 됩니다
  - **왜 "한 번에 하나씩"이 중요할까요? — AI 구조적 한계 3가지** (출처: 개요보강.md lines 166-181):
    1. **토큰 제한**: AI가 한 번에 읽고 쓸 수 있는 양에 물리적 한계가 있어요
    2. **대화 압축 → 맥락 소실**: 대화가 길어지면 AI가 이전 내용을 압축 → 중요한 맥락이 빠져요
    3. **UX 판단 불가**: "이게 내가 원하던 느낌이야"는 결국 사람만 판단 가능
  - **"잘했겠지" 전제의 위험** (출처: 개요보강.md lines 183-194):
    - 기능 A 만들고 → 확인 안 하고 → 기능 B 만들고 → 확인 안 하고... → 나중에 보면 기능 A에 버그
    - 마치 **1층 기둥이 비뚤어진 줄 모르고 2층, 3층 올린 아파트**처럼
    - 그래서 **"하나 만들고 → 확인하고 → 다음"**이 결국 더 빨라요
  - **정확한 용어 사용 예시**:
    | 모호한 표현 | 정확한 표현 | 효과 |
    |---|---|---|
    | "보이는 부분" | "프론트엔드" | AI가 정확히 어떤 코드를 수정할지 앎 |
    | "데이터 어딘가 저장해" | "localStorage에 저장해" | 저장 방식까지 명확하게 지정 |
    | "빠르게 해줘" | "응답 시간 2초 이내로" | 구체적 수치로 검증 가능 |
- **비유**: 유능한 신입사원한테 "알아서 해"라고 하면 엉뚱한 결과. "이 고객 데이터를 이 기준으로 정리해줘"라고 하면 완벽한 결과.
- **셀프체크**:
  - AI에게 "알아서 해줘"라고 하면? → 엉뚱한 결과
  - 코드를 "짜는 것"과 "보는 것" 중 바이브 코더에게 필요한 것은? → 보는 것
  - 대화가 길어질수록 AI가 실수하는 이유는? → 토큰 제한 (앞 내용을 잊음)
- **다음 섹션 예고**: "마인드셋이 잡혔으니, 도구를 설치해볼 거예요. 4가지 무기를 세팅하러 가볼까요?"
- **참고 자료**: `02-바이브코더가-알아야할것.md`, `03-유능한상사되기.md`

### 섹션 3: 도구 세팅 — 4가지 무기 (tools) [10분]

- **핵심 메시지**: 터미널, VS Code, Git, NPM — 이 4가지만 있으면 바이브 코딩 준비 완료
- **Hook**:
  > 터미널이라고 하면 겁부터 나시죠? 까만 화면에 깜빡이는 커서... 근데 사실 카카오톡이랑 똑같아요.
- **리캡**: "마인드셋을 잡았으니, 실전 준비를 해볼게요. 터미널부터 NPM까지 6단계로 세팅해요."
- **포함 요소**: 4대 도구 정리 테이블, 각 도구별 비유 + 설치 명령어, 설치 완료 후 확인 방법
- **주요 내용**:
  - **터미널 기초 명령어 5가지** (NEW - 출처: Part 2 Ch.06):
    | 명령어 | 뜻 | 마우스 동작 | 예시 |
    |---|---|---|---|
    | `cd 폴더명` | Change Directory | 폴더 더블클릭 | `cd my-project` |
    | `cd ..` | 상위 폴더로 | 뒤로가기 | `cd ..` |
    | `ls` | List (목록 보기) | 눈으로 확인 | `ls` |
    | `mkdir 이름` | Make Directory | 우클릭→새폴더 | `mkdir my-news-bot` |
    | `pwd` | Print Working Directory | 주소 표시줄 | `pwd` |
    - **5분 실습 "AI의 집 짓기"**: pwd → mkdir my-house → cd my-house → mkdir living-room → ls
    - **왜 배우나요?**: AI가 에러 내면 ls로 현재 폴더 확인, cd로 이동해야 해요
    - **rm 주의**: 터미널 삭제는 휴지통을 거치지 않아요 (영구 삭제)
  - **도구 1: Claude Code — "손발이 달린 AI"**
    - 웹 ChatGPT/Claude = "말만 하는" 조언자 (코드 복붙은 내가)
    - Claude Code = "손발이 달린" 실무자 (파일 생성/수정/실행까지 직접)
    - **GUI vs CLI 비교** (출처: `04-클로드코드-설치.md`):
      - GUI(그래픽 방식): 마우스로 폴더 우클릭 → "새 폴더" 클릭 → 이름 입력
      - CLI(터미널 방식): `mkdir my-folder` 한 줄이면 끝
      - 똑같은 결과인데, 터미널이 더 빨라요. 그리고 AI가 터미널 명령을 직접 실행할 수 있어요.
    - 설치: `npm install -g @anthropic-ai/claude-code` → `claude` 실행
    - **설치 확인**: `claude --version` (버전 번호가 나오면 성공) (출처: `04-클로드코드-설치.md`)
    - **트러블슈팅** (출처: `04-클로드코드-설치.md`):
      - `npm: command not found` 오류가 나오면? → Node.js LTS 버전을 먼저 설치해야 해요 (nodejs.org)
      - Node.js를 설치하면 npm이 자동으로 함께 설치돼요
    - **"첫 업무 지시" 대화 예시** (출처: `04-클로드코드-설치.md`):
      - 나: "현재 폴더에 있는 파일 목록 좀 보여줘"
      - Claude: `ls` 명령어를 자동 실행하고 결과를 보여줘요
      - 나: "여기에 hello.txt 파일 만들어줘. 내용은 '안녕하세요'로"
      - Claude: 파일을 직접 생성해요. 복붙할 필요 없어요!
    - 비유: 카카오톡(사람↔사람) vs 터미널(사람↔컴퓨터)
  - **도구 2: VS Code — "전문 주방"**
    - **개발자 70% 이상이 사용하는 에디터** — 가장 많이 쓰는 데는 이유가 있어요 (출처: `05-VSCode-세팅.md`)
    - 3요소: 탐색기(냉장고) + 에디터(도마) + 터미널(가스레인지)
    - **자동 완성** 기능: `cl`만 쳐도 `console.log`를 추천해줘요. 타이핑을 줄여줘요. (출처: `05-VSCode-세팅.md`)
    - **에러 표시**: 문제가 있는 코드 아래 빨간 줄이 나와요. 마우스를 올리면 뭐가 잘못됐는지 알려줘요. (출처: `05-VSCode-세팅.md`)
    - 핵심 명령: `code .` = "현재 폴더를 VS Code로 열어"
    - 확장: Korean Language Pack 설치
    - **실습: 파일 만들고 저장하기** (5단계) (출처: `05-VSCode-세팅.md`):
      1. 터미널에서 `code .` 입력 (현재 폴더를 VS Code로 열기)
      2. 왼쪽 탐색기에서 "새 파일" 아이콘 클릭
      3. 파일명 입력: `hello.txt`
      4. 오른쪽 에디터에 내용 입력: "안녕하세요, 첫 파일이에요!"
      5. `Ctrl+S`로 저장
    - **팁**: 파일명 옆에 동그라미(●)가 보이면 = 아직 저장 안 된 거예요. `Ctrl+S` 누르면 사라져요. (출처: `05-VSCode-세팅.md`)
  - **도구 3: Git — "게임 세이브"**
    - **첫 시작 명령**: `git init` — 이 폴더에서 세이브 기능을 켠다는 뜻이에요 (출처: `06-Git-기초.md`)
    - Commit = 세이브 포인트 찍기
    - 3단계 주문: `git add .`(담고) → `git commit -m "메시지"`(찍고) → `git push`(밀고)
    - GitHub = 클라우드 세이브 (컴퓨터 고장나도 안전)
    - **RPG 비유 디테일** (출처: `06-Git-기초.md`):
      - "보스를 잡기 전에 저장! 로그인 기능 건드릴 건데, 망치면 귀찮으니까 여기서 일단 저장!"
      - `git commit -m "로그인 건드리기 전 세이브"` → 마음의 평화
      - 망쳤으면? 세이브 포인트로 돌아가면 돼요.
  - **도구 4: NPM + .env — "레시피북 + 금고"**
    - package.json = 재료 목록(레시피), `npm install` = 한번에 장보기
    - **"내 컴퓨터에서만 작동 안 함" 문제 해결** (출처: `07-환경세팅.md`):
      - 팀원이 "내 컴퓨터에서 안 되는데?"라고 하면? → `npm install` 한 번이면 해결
      - package.json에 재료 목록이 있으니까, 누구든 `npm install`로 같은 환경을 만들 수 있어요
    - .env = 비밀번호 금고 (API 키, 비밀번호는 여기에만)
    - node_modules = 재료 보관함 (Git에 안 올림, 언제든 재설치)
    - **.gitignore 상세** (출처: `07-환경세팅.md`):
      - `node_modules/` → 재료 보관함은 올리지 않아요 (용량도 크고, `npm install`로 재설치 가능)
      - `.env` → 비밀번호 금고는 절대 올리면 안 돼요 (API 키 유출 위험!)
      - .gitignore 파일에 이 두 줄을 써두면, Git이 자동으로 무시해요
  - **4대 도구 종합 테이블**:
    | 도구 | 비유 | 역할 | 핵심 명령어 |
    |------|------|------|-----------|
    | Claude Code | 손발 달린 신입 | AI 코딩 실행 | `claude` |
    | VS Code | 전문 주방 | 코드 편집 환경 | `code .` |
    | Git | 게임 세이브 | 버전 관리 | `git init → add → commit → push` |
    | NPM | 레시피북 | 의존성 관리 | `npm install` |
- **셀프체크**:
  - 현재 폴더의 파일 목록을 보는 명령어는? → `ls`
  - Claude Code 설치 확인 명령어는? → `claude --version`
  - 현재 폴더를 VS Code로 여는 명령어는? → `code .`

### 섹션 4: 실전 — 뉴스 봇 만들기 (hands-on) [20분]

- **핵심 메시지**: AI와 대화하면서, 진짜 동작하는 자동화 비서를 직접 만들어봐요
- **Hook**:
  > "매일 아침 뉴스 검색하는 데 30분... 1년이면 180시간. 지금부터 이 30분을 0분으로 만드는 비서를 만들어볼 거예요."
- **리캡**: "도구 세팅까지 마쳤어요. Claude Code, VS Code, Git, NPM이 모두 준비된 상태예요."
- **포함 요소**: 자동화 3조건, AI 기획 대화(프롬프트 분석 포함), 3단계 실전 구현, 기술 정리 테이블
- **스토리 아크**: 공감(왜?) → 기획(AI 대화) → Step1 수집 → Step2 전송 → Step3 자동화 → 완성
- **주요 내용**:
  - **자동화 적합성 판단**: 반복적 + 규칙적 + 데이터 처리 = 자동화 가능
  - **AI와 기획 대화** (프롬프트 설명 포함):
    - 1단계: 큰 그림 전달 — "뭘 하고 싶은지 + 언제 + 어디로" 3요소
    - 2단계: 모르는 건 바로 물어보기 — "쉽게 설명해줘" 패턴
    - 3단계: 디테일 잡기 — "1단계부터 시작하자" (범위 좁히기)
  - **[STEP 1] 데이터 수집 — RSS**:
    - 크롤링 vs RSS 비교 (크롤링=몰래 가져오기, RSS=공식 전단지)
    - 파싱 = 보석 추출
    - AI 프롬프트 분석: 라이브러리 지정, 수량 명시, 데이터 지정, 파일명 지정, 한글 주석
    - Google News RSS URL 형식
    - 코드 핵심 부분 설명
  - **[브릿지 1→2]**: "터미널에서만 볼 수 있어요 → 슬랙으로 보내면 폰에서 확인 가능"
  - **[STEP 2] 슬랙 전송 — Webhook**:
    - 슬랙 앱 만들기 6단계
    - Webhook URL = 비밀 우체통 → .env에 보관
    - AI 프롬프트 분석: 기존 파일에 추가, 함수명 지정, 보안 패턴, 메시지 형식
    - POST 방식 설명 (GET=가져오기, POST=보내기)
    - sendToSlack 함수 핵심 코드
  - **[브릿지 2→3]**: "매번 직접 실행해야 하나요? → Cron(알람 시계) + GitHub Actions"
  - **[STEP 3] 24/7 자동화 — GitHub Actions**:
    - GitHub Actions = 무료 대리인
    - AI 프롬프트 분석: 한국 시간, 파일 경로, Node 버전, Secrets 사용
    - UTC vs KST 변환표
    - GitHub Secrets 등록 5단계
    - 배포: git add → commit → push
  - **완성 + 기술 정리 테이블**: RSS, 파싱, Webhook, Cron, GitHub Actions
- **셀프체크**:
  - RSS와 크롤링의 차이는? → RSS = 공식 제공 피드, 크롤링 = 직접 긁어옴
  - Webhook URL을 코드에 직접 넣으면 안 되는 이유는? → 유출 시 아무나 메시지 발송 가능
  - GitHub Actions에서 한국 9시 = UTC 몇 시? → UTC 0시
  - `node index.js` 없이 자동 실행하려면? → GitHub Actions + Cron 스케줄
- **참고 자료**: `08-자동화-아이디어.md`, `09-데이터-수집정리.md`, `10-슬랙봇-만들기.md`, `11-정기실행-GitHub-Actions.md`
