처음엔 잘 되는데...

처음에 AI한테 시키면 뭔가 그럴듯한 게 나와요. "오, 진짜 되네?" 하고 신나요.

그래서 기능을 하나 더 추가해요. "여기에 로그인도 붙여줘"

그런데 갑자기 아까 되던 게 안 돼요. 에러가 줄줄 나와요. 어디를 고쳐야 하는지도 모르겠어요.

결국 "처음부터 다시 하자" → 3번째 반복하면... 포기.

이건 AI가 무능해서가 아니에요. 시키는 방법을 몰라서예요.

도구 탓이 아니에요. 지휘자의 문제예요. AI의 능력은 이미 놀라울 정도로 발전했어요. 그렇다면 왜 여전히 실패할까요? 답은 간단해요 — 그 능력을 끌어내는 방법을 아직 모르기 때문이에요.

세상이 바뀌고 있어요

🔥 마이크로 서비스의 폭발 "이 기능 하나만 잘하면 돼" → AI로 빠르게 출시
💰 가격 경쟁의 시작 개발팀 10명 → 1~2명. 인건비 절감 → 가격 파괴
🏃 소규모 팀의 강세 대기업 의사결정 3개월, 소규모 팀은 3일

이건 먼 미래 얘기가 아니에요. 지금 일어나고 있어요. 비개발자가 AI로 업무 자동화 툴을 만들어 팀에 배포하고, 1인 창업자가 AI로 SaaS를 만들어 월 수천만원 수익을 올리고 있어요.

AI 코딩의 발전 과정

시기 수준 한계
2020년 이전 "if문 예제 알려줘" → 코드 조각만 조립은 직접

2024년~현재 (Claude Code) "앱 만들어줘" → 프로젝트 전체 생성 지휘하는 법을 알아야 함

결국 차이는 "명령하는 사람"

🤖 AI 성능은 다 똑같아요 ChatGPT든 Claude든, 능력은 비슷해요
🎯 차이는 "어떻게 시키느냐" 같은 AI, 다른 결과
📚 이 특강이 그걸 알려드려요 "어떻게 시키느냐"의 기술
🎯

  • AI와 대화해서 IT 속보 슬랙 봇을 처음부터 끝까지 만들 수 있어요

바이브 코딩이란

개요에서 AI 코딩 시대가 왔다는 걸 봤어요. 그런데 정확히 "바이브 코딩"이 뭘까요?

🎯

바이브 코딩 = 코드 대신, 명확한 의도와 예상 결과로 AI를 지휘하는 것

"바이브"면 대충 느낌만 전달하면 되는 거 아니에요?
— 아닙니다. 여기서 오해하면 안 돼요.

정의

코드 한 줄 한 줄 짜는 게 아니라,
"이 버튼 누르면 이렇게 동작해야 해"라고 의도와 예상 결과를 구체적으로 지시하는 방식이에요.

바이브 코딩 ≠ 대충 말하기

"바이브"라는 단어 때문에 헷갈릴 수 있어요. "느낌만 전달하면 AI가 알아서 해주겠지?" — 이게 안 돼서 다들 막히는 거예요.

바이브 코딩의 진짜 의미:

  • 코드 문법은 몰라도 돼요
  • 대신 뭘 만들지, 왜 만들지, 어떻게 동작해야 하는지는 명확히 알아야 해요
  • AI한테 기술적인 지침을 정확하게 전달하는 게 핵심이에요

MVP란?

MVP(Minimum Viable Product) = 최소 기능 제품. 핵심 기능만 있는 버전을 빨리 만들어서 반응을 보는 거예요. 바이브 코딩은 이 MVP를 빠르게 만드는 데 특히 강해요.

전통 코딩 vs 바이브 코딩

전통적인 코딩

  • 사람이 직접 코드를 짠다
  • 문법, 규칙을 외워야 한다
  • 오류 하나에 몇 시간 고민
  • 혼자 모든 걸 알아야 한다

바이브 코딩

  • AI가 코드를 짜고, 사람이 방향을 잡는다
  • 의도와 결과를 명확하게 지시한다
  • AI한테 물어보면 바로 해결책 제시
  • AI와 대화하면서 같이 만든다

전통 코딩: 벽돌을 직접 쌓는 것 vs 바이브 코딩: AI와 함께 설계하는 것

왜 지금 바이브 코딩이 가능해졌을까요? 2022년까지는 AI가 코드 조각만 줄 수 있었어요. 복붙과 조립은 직접 해야 했죠. 하지만 2024년부터 AI가 프로젝트 전체를 다룰 수 있게 됐어요. 파일 생성, 코드 작성, 에러 수정까지. 남은 건 "어떻게 시키느냐"뿐이에요.

같은 목표, 다른 접근

할일 관리 앱을 만든다고 하면:

전통 방식

  • 프로그래밍 언어 선택 (JavaScript? Python?)
  • 문법 공부 (변수, 함수, 조건문...)
  • 프레임워크 학습 (React? Vue?)
  • 코드 작성 → 에러 → 구글 검색 → 삽질
  • 6개월~1년 후에 겨우 간단한 앱 하나

바이브 코딩

  • AI에게 말하기: "할 일 관리 앱 만들고 싶어"
  • AI가 물어봄: "어떤 기능이 필요해요?"
  • 대화하며 기획 → AI가 코드 작성
  • 피드백: "버튼이 너무 작아. 더 크게" → 수정
  • 대화할 줄 알면 바로 시작 가능

바이브 코딩으로 뭘 만들 수 있나요?

코딩 경험 없는 사람들이 실제로 바이브 코딩으로 만드는 것들이에요.

⚙️ 업무 자동화 뉴스 봇, 엑셀 자동 병합, 이메일 분류
🌐 웹사이트 / 서비스 포트폴리오, 스터디 모임, 소규모 쇼핑몰
📱 간단한 앱 습관 트래커, 가계부, 운동 기록
📊 데이터 분석 매출 대시보드, 설문 분석, 가격 모니터링

이 사람들이 코딩을 배웠을까요? 아니에요. AI와 대화하는 법을 배웠어요.

바이브 코딩의 핵심은 "대화"

💬 말하기 AI에게 요청
→
👀 확인 결과 살펴보기
→
🔄 피드백 "이건 좋고, 저건 고쳐줘"
→
🔁 반복 완성될 때까지

한 번에 완성품이 나오지 않아요. 대화하면서 만들어가는 거예요.

바이브 코딩식 대화법 맛보기

이렇게 하면 실패

❌ "투두 앱 만들어줘"

→ AI: 뭔가 만들긴 하는데... 이게 내가 원하던 거야?

이렇게 하면 성공

✅ "할 일 관리 앱을 만들고 싶어. 어떤 기능들이 필요할지 같이 정리해볼까?"

→ AI: "네, 먼저 핵심 기능부터 정리해볼게요..."

"만들어줘"가 아니라 "같이 정리해보자"예요. AI와 대화하면서 기획이 잡히는 거예요.

바이브 코딩을 하다 보면

처음
AI가 뭘 하는지 하나도 몰라요. "뭔가 막 만드네..."
몇 번 하다 보면
"아, 지금 로그인 부분 고치고 있구나" "여기서 에러 난 건 이것 때문이겠네"
결국
코드를 짤 줄은 몰라도, 볼 줄은 알게 돼요. 이게 성장이에요.
자동차를 직접 만들 줄 몰라도 운전은 할 수 있어요.
근데 운전하려면 적어도 이건 알아야 해요:

엑셀이 뭐고 브레이크가 뭔지 → 기본 개념
신호등이 뭘 의미하는지 → 에러/경고 읽기
어디로 가고 싶은지 → 만들 목표

AI가 차를 만들어주지만, 운전은 여러분이 해요.

여러분은 방향(Direction)을, AI는 코드(Code)를 담당해요

바이브 코딩이 뭔지 알게 됐어요. 그런데 AI한테 어떻게 시켜야 잘 할까요? 다음 섹션에서 "유능한 상사"가 되는 법을 배워볼게요.

AI의 유능한 상사 되기

바이브 코딩이 "명확한 의도로 AI를 지휘하는 것"이란 걸 배웠어요. 그러면 어떻게 지휘해야 할까요?

🎯

AI는 유능한 신입사원. 뭘 만들지 모르는 건 AI가 아니라 여러분의 문제예요.

"만들어줘" 한마디면 될 줄 알았는데...
왜 내가 원하는 게 안 나오죠?

몰라도 되는 것 vs 알아야 하는 것

몰라도 됨 알아야 함
프로그래밍 언어 문법 뭘 만들고 싶은지 (목적)
복잡한 알고리즘 프로그램의 종류 (웹? 앱? 자동화?)
코드를 직접 타이핑하는 것 AI 결과를 확인하고 피드백하는 법
function, const 같은 키워드 "이건 로그인 기능이구나" 판독 능력

여러분의 업무 지식이 곧 무기예요.
"우리 서비스는 7일 이내만 환불 가능한데, AI는 이걸 몰라요." — AI 시대의 경쟁력은 코딩 실력이 아니라 업무와 비즈니스에 대한 이해도예요. 프로그래밍 문법은 AI가 대신하지만, "이 기능이 우리 고객에게 왜 필요한지"는 여러분만 알아요.

"알아서 해줘"의 함정

많은 분이 이렇게 생각해요: "할 일 추가, 삭제, 완료 체크. 완료한 건 아래로. 스마트폰에서 돌아가게" — 이 정도면 구체적인 거 아냐?

아니에요. 이것도 "알아서 해줘"예요. 왜냐면 AI는 이런 걸 모르거든요:

  • "할 일 추가" 버튼이 어디에 있어야 하는지
  • 완료 체크하면 바로 내려가야 하는지, 애니메이션이 있어야 하는지
  • "오늘 할 일" 화면에서 뒤로 가기 누르면 어디로 가야 하는지

기능 목록을 줘도, "사용자 경험"은 AI가 알아서 못 만들어요.

진짜 구체적 지시 = 한 입 크기로

1단계: 기획 문서 먼저
"이 앱이 뭔지, 누가 쓰는지, 핵심 기능이 뭔지" — AI한테 같이 정리하자고 해도 OK
2단계: 기능 하나씩 지시
"먼저 할 일 추가 버튼만 만들어줘" → 확인하고, 피드백하고, 다음으로
3단계: 바로바로 피드백
"버튼 위치가 애매한데, 오른쪽 아래로 옮겨줘" → 고치고, 확인하고, 다음으로

개념이 필요한 두 가지 이유

1. 명확한 지시

"알아서 해줘"가 아니라 구체적인 주문서가 돼요. 개념을 알아야 정확히 시킬 수 있어요.

2. AI 결과 판단

AI가 만들어준 결과물을 평가할 수 있어야 해요. "이게 맞는 건가?" 판단하려면 기본 개념이 필요해요.

코드 "짜기" vs "보기"의 차이

바이브 코딩은 코드를 직접 쓰는 게 아니에요. 하지만 AI가 만든 코드를 읽고 판단하는 능력은 필요해요. 아래 예시를 볼게요.

function addTodo(text) {
  const newTodo = {
    id: Date.now(),
    text: text,
    done: false
  };
  todos.push(newTodo);
}

짜는 것 (몰라도 됨)

  • function, const 같은 키워드
  • Date.now() 같은 함수 사용법
  • todos.push() 같은 배열 조작 문법

보는 것 (알아야 함)

  • "할 일을 추가하는 기능이구나"
  • "새 할 일에 id, 텍스트, 완료 여부가 들어가는구나"
  • "목록에 추가하는 동작이구나"

짜는 건 AI가 해요. 보고 판단하는 건 여러분 몫이에요. "이 코드가 뭘 하는 건지" 흐름을 읽을 줄 알면 돼요.

전통 코딩 학습 vs 바이브 코딩 학습

전통 코딩 학습

"for문을 어떻게 쓰는지", "if문 다음에 뭐가 와야 하는지"

→ 문법 세부사항에 집중

바이브 코딩 학습

"이 데이터를 하나씩 처리해야 해", "여기서 에러 체크가 필요해"

→ 의도와 개념 이해에 집중

5단계 성장 경로

기능 요청 수준
"로그인 만들어줘" (시작점)
명세 제공 수준 ← 오늘의 목표
"이메일+비밀번호 입력, 유효성 검사 포함"
구조 이해 수준
"프론트는 React, 백엔드는 Node.js로"
설계 대화 수준
"아키텍처 추천해봐" → 판단 → "이렇게 해줘"
고도화
성능/보안/확장성까지 고려

대화법 3단계 비교

같은 "상품 검색/필터" 기능이라도 지시 수준에 따라 결과가 완전히 달라요.

수준 1: 막연한 지시

"상품 검색 기능 만들어줘"

→ 검색창만 있고 필터 없음. 필터 추가하니 기존 검색 망가짐. 뭐가 문제인지도 모름.

수준 2: 구체적 지시

"검색창 + 카테고리 필터(의류/전자/식품) + 가격대 필터(1만 이하/1~5만/5만 이상)"

→ 기능은 나옴. 근데 상품 1000개 넘으면 느려짐. 구조 문제에 대응 어려움.

수준 3: 기술적 지시 (목표)

"상품 검색/필터 만들 건데, 방식 먼저 정하자. 상품 많아질 수 있어서 성능도 고려."
→ AI: "프론트 필터링 vs 백엔드 API 필터링 두 가지 있어요"
→ "일단 1번으로 가고, 나중에 바꾸기 쉽게 구조 잡아줘"

→ 방식의 장단점을 듣고 내가 판단. 구조를 이해하고 있어서 문제 생기면 어디를 고칠지 앎.

정확한 용어를 쓰면 AI가 더 잘 이해해요

모호한 표현 정확한 표현 효과
"보이는 부분" "프론트엔드" AI가 정확히 어떤 코드를 수정할지 앎
"데이터 어딘가 저장해" "localStorage에 저장해" 저장 방식까지 명확하게 지정
"빠르게 해줘" "응답 시간 2초 이내로" 구체적인 수치로 검증 가능

용어를 외울 필요는 없어요. AI한테 "이걸 뭐라고 부르지?" 물어보면 돼요. 중요한 건 "그런 개념이 있다는 걸 아는 것"이에요.

기술적 지시가 가능한 매니저의 특징

선택지 물어보기

상황에 맞게 판단

직접 코딩하지 않기
코드 타이핑 X, 버그 직접 수정 X — 대신 정확히 지시해요

유능한 매니저의 3가지 조건

조건구체적으로
뭘 만들지 명확히 하기"이런 사람이 이렇게 쓸 앱이야" — 기획 문서로 정리

3가지 마인드셋

🔄 "한 번에 안 돼도 괜찮아" 대화하면서 고쳐나가면 돼요
🧭 "내가 방향을 잡아야 해" AI가 다 해주는 게 아니에요
🌱 "조금씩 배워가면 돼" 하나씩 만들다 보면 자연스럽게 알게 돼요

왜 "한 번에 하나씩"이 중요할까요?

기술적인 이유가 3가지 있어요.

📏 1. 토큰 제한 AI가 한 번에 읽고 쓸 수 있는 양에 물리적 한계가 있어요
🧠 2. 대화 압축 → 맥락 소실 대화가 길어지면 AI가 이전 내용을 압축 → 중요한 맥락이 빠져요
🖱️ 3. UX 판단 불가 "이게 내가 원하던 느낌이야"는 결국 사람만 판단 가능

"잘했겠지" 전제의 위험
기능 A 만들고 → 확인 안 하고 → 기능 B 만들고 → 확인 안 하고...
나중에 보면 기능 A에 버그가 있어요. 근데 그 위에 B, C, D를 쌓아버렸어요.

마치 1층 기둥이 비뚤어진 줄 모르고 2층, 3층 올린 아파트처럼요.
나중에 고치려면? 거의 처음부터 다시 해야 해요.

그래서 "하나 만들고 → 확인하고 → 다음"이 결국 더 빨라요.

유능한 신입사원한테 "알아서 해"라고 하면 엉뚱한 결과.
"이 고객 데이터를 이 기준으로 정리해줘"라고 하면 완벽한 결과.

셀프 체크

질문 정답
AI에게 "알아서 해줘"라고 하면? 엉뚱한 결과가 나와요
코드를 "짜는 것"과 "보는 것" 중 바이브 코더에게 필요한 것은? 보는 것 (구조와 흐름 이해)
대화가 길어질수록 AI가 실수하는 이유는? 토큰 제한 — 앞 내용을 잊어요

1Step 1: 터미널 이해하기

터미널이라고 하면 겁부터 나시죠? 까만 화면에 깜빡이는 커서...

카카오톡 비유로 이해하기

카카오톡은 사람 ↔ 사람 사이의 대화창이에요. 터미널은 사람 ↔ 컴퓨터 사이의 대화창이에요. 카카오톡에서 친구한테 "사진 보내줘"라고 하듯, 터미널에서 컴퓨터한테 "파일 목록 보여줘"라고 하는 거예요. 그게 전부에요!

GUI vs CLI 비교

지금까지 여러분은 마우스로 폴더를 클릭하고, 우클릭해서 새 폴더를 만들었죠? 그게 GUI 방식이에요. 터미널은 같은 일을 글자(명령어)로 하는 CLI 방식이에요.

GUI (마우스 방식)

폴더 우클릭 → "새 폴더" → 이름 입력

CLI (터미널 방식)

mkdir my-folder 한 줄이면 끝!

AI가 터미널 명령을 직접 실행할 수 있어요

왜 굳이 CLI를 배워야 할까요? 바로 AI가 마우스를 못 쓰기 때문이에요. AI는 터미널 명령어는 직접 실행할 수 있지만, 마우스 클릭은 못 해요. 그래서 터미널을 쓰면 AI에게 일을 시킬 수 있는 거예요!

터미널 여는 법

🍎 Mac

Command + Space → "Terminal" 검색 → 엔터

🪟 Windows

윈도우 키 → "PowerShell" 검색 → 엔터

2Step 2: 터미널 기초 명령어 5가지

터미널을 열었으니, 기본 조작법을 먼저 배워볼게요. 딱 5개만 알면 돼요.

명령어 뜻 마우스로 하면 예시
cd 폴더명 Change Directory (이동) 폴더 더블클릭 cd my-project
cd .. 상위 폴더로 뒤로가기 버튼 cd ..
ls List (목록 보기) 폴더 안을 눈으로 확인 ls
mkdir 이름 Make Directory (폴더 만들기) 우클릭 → 새 폴더 mkdir my-news-bot
pwd Print Working Directory 탐색기 주소 표시줄 pwd

5분 실습: "AI의 집 짓기"

직접 따라 쳐보세요! 터미널에서 폴더를 만들고 이동하는 연습이에요.

pwd                    # 나 지금 어디 있지?
mkdir my-house         # 집을 만들자
cd my-house            # 집 안으로 들어가자
mkdir living-room      # 거실을 만들자
mkdir kitchen          # 부엌도 만들자
ls                     # 뭐가 있는지 확인!

ls를 치면 living-room과 kitchen이 보이면 성공이에요!

"AI가 다 해주는데 왜 이걸 배우나요?"
AI가 "파일을 찾을 수 없습니다" 에러를 내면, 여러분이 ls로 현재 폴더를 확인하고 cd로 올바른 위치로 이동해야 해요. 유능한 상사는 신입이 막혔을 때 상황을 파악하고 방향을 잡아줄 수 있어야해요.

주의: rm (삭제) 명령어
rm 파일명으로 파일을 지울 수 있어요. 하지만 터미널에서 삭제하면 휴지통을 거치지 않아요! 영구 삭제되니까 조심하세요. 지금은 몰라도 되고, 나중에 필요할 때 AI에게 물어보면 돼요.

기본 이동법을 배웠으니, 이제 AI 도우미를 설치해볼게요!

3Step 3: Claude Code 설치하기

웹 브라우저에서 ChatGPT를 써보셨죠? 거기서는 AI가 코드를 "보여주기만" 해요. 여러분이 직접 복사해서 붙여넣어야 하죠. Claude Code는 달라요. 터미널에서 직접 파일을 만들고, 수정하고, 실행까지 해요. 말 그대로 "손발이 달린 AI"예요.

설치 3단계

1단계: 아까 열어둔 터미널에 설치 명령어를 입력해요.

npm install -g @anthropic-ai/claude-code

2단계: 설치가 끝나면 Claude Code를 실행해요.

claude

3단계: 브라우저가 자동으로 열려요. Claude 계정으로 로그인하면 승인 완료!

설치 확인: claude --version을 입력해서 버전 번호가 나오면 성공이에요!

트러블슈팅: npm: command not found 오류가 나오면? → Node.js LTS 버전을 먼저 설치하세요 (nodejs.org). Node.js를 설치하면 npm이 자동으로 함께 설치돼요.

첫 업무 지시해보기

설치가 됐으니 바로 써볼까요? claude를 실행한 상태에서 한국어로 말하면 돼요.

나: "현재 폴더에 있는 파일 목록 좀 보여줘"
Claude: ls 명령어를 자동 실행하고 결과를 보여줘요
나: "여기에 hello.txt 파일 만들어줘. 내용은 '안녕하세요'로"
Claude: 파일을 직접 생성해요. 복붙할 필요 없어요!

명령어를 몰라도 AI가 알아서 처리해요. 터미널 명령어를 외울 필요 없어요. 한국어로 말하면 AI가 알아서 실행해요. 이게 바로 바이브 코딩의 핵심이에요!

Claude Code가 준비됐어요! 이제 코드를 편하게 볼 수 있는 작업 환경을 만들어볼까요?

4Step 4: VS Code 세팅하기

VS Code (Visual Studio Code)는 전 세계 개발자의 70% 이상이 사용하는 전문가용 작업 환경이에요. Claude Code가 만든 코드를 눈으로 확인하고, 직접 수정할 수 있는 공간이에요.

설치 방법

  1. VS Code 공식 홈페이지 접속
  2. 파란색 Download 버튼 클릭
  3. 설치 파일 실행 → "다음, 다음, 완료"

VS Code 해부하기

VS Code를 열면 3가지 영역이 보여요. 주방에 비유하면 이해가 쉬워요.

  • 탐색기(왼쪽 패널) = 냉장고 — 프로젝트 파일을 보관하고 꺼내는 곳
  • 에디터(가운데) = 도마 — 코드를 열어놓고 직접 편집하는 곳
  • 터미널(아래쪽) = 가스레인지 — 명령어를 실행하는 곳 (여기서 Claude Code도 돌려요!)

주요 기능 3가지

  • 자동 완성: cl만 쳐도 console.log를 추천해줘요
  • 에러 표시: 문제 있는 코드 아래 빨간 줄이 나와요
  • 터미널 내장: 별도 창 없이 VS Code 안에서 터미널을 쓸 수 있어요

필수 확장 프로그램: Korean Language Pack

  1. VS Code 왼쪽 사이드바에서 확장(Extensions) 아이콘 클릭
  2. 검색창에 Korean 입력
  3. "Korean Language Pack for Visual Studio Code" → Install → Restart

code . 명령어

code .    # "현재 폴더를 VS Code로 열어"

code는 "VS Code를 실행해", .(점)은 "현재 폴더를 열어"라는 뜻이에요. 터미널에서 프로젝트 폴더로 이동한 뒤 code .을 입력하면 해당 폴더가 VS Code에서 열려요.

터미널 여는 법: VS Code 안에서 터미널이 안 보일 때 → 상단 메뉴 Terminal → New Terminal 또는 단축키 Ctrl + ` (백틱). 터미널은 VS Code 아래쪽에 나타나요.

실습: 파일 만들고 저장하기

  1. code . 명령어로 VS Code 열기
  2. 탐색기 빈 공간 우클릭 → "새 파일"
  3. 파일명 입력: hello.txt
  4. 내용 입력: "안녕하세요, 첫 파일이에요!"
  5. Ctrl+S로 저장

팁: 파일명 옆에 동그라미(●)가 보이면 = 아직 저장 안 된 거예요. Ctrl+S 누르면 사라져요.

파일을 만들었으니, 이제 안전하게 저장하는 법을 배워볼게요!

5Step 5: Git — 게임 세이브

RPG 게임 해보셨죠? 보스전 앞에서 반드시 세이브하잖아요. 코딩도 똑같아요. "로그인 기능 건드릴 건데, 망치면 귀찮으니까 여기서 일단 저장!" — 이게 Git이에요.

Git 시작하기

프로젝트 폴더에서 터미널을 열고 이 명령어를 입력하면 Git이 시작돼요.

git init

Initialized empty Git repository가 뜨면 성공이에요! 이 폴더에서 세이브 기능이 켜진 거예요.

Git 3단계 주문: 담고 → 찍고 → 밀고

Git은 딱 3줄만 기억하면 돼요.

git add .           # 담고 (점 . = "모든 파일 다 담아!")
git commit -m "메시지"  # 찍고 (세이브 포인트 찍기)
git push             # 밀고 (클라우드에 올리기)

RPG 비유: "보스를 잡기 전에 저장! 로그인 기능 건드릴 건데, 망치면 귀찮으니까 여기서 일단 저장!" → git commit -m "로그인 건드리기 전 세이브" → 마음의 평화. 망쳤으면? 세이브 포인트로 돌아가면 돼요.

이것만 알면 코드는 절대 날아가지 않아요.

GitHub 연결하기 (클라우드 세이브)

GitHub = 클라우드 세이브. 내 컴퓨터가 고장나도 코드가 안전해요. GitHub에서 저장소를 만든 후, 이 3줄만 터미널에 붙여넣으면 연결 끝!

  1. GitHub.com 회원가입
  2. + → New repository → 이름 짓기 → Create repository
  3. 아래 3줄을 터미널에 붙여넣기:
git remote add origin https://github.com/내아이디/내저장소.git
git branch -M main
git push -u origin main

이제 git push 한 번이면 내 코드가 클라우드에 저장돼요.

코드가 안전하게 저장되고 있어요! 마지막으로, 프로젝트에 필요한 도구들을 세팅해볼게요.

6Step 6: NPM + .env

NPM = 프로젝트 재료 관리자

NPM(Node Package Manager)은 프로젝트에 필요한 라이브러리를 관리하는 도구예요. 다른 사람이 만든 프로젝트를 받았는데 "내 컴퓨터에서만 작동 안 함"... 이런 경험 있으시죠? NPM이 이 문제를 해결해줘요.

package.json = 레시피 파일

프로젝트에 필요한 재료(라이브러리) 목록이 적혀있는 파일이에요.

{
  "name": "my-project",
  "dependencies": {
    "rss-parser": "^3.13.0",
    "axios": "^1.13.0"
  }
}

npm install을 실행하면 package.json에 적힌 모든 라이브러리가 node_modules 폴더에 자동으로 설치돼요. 레시피만 있으면 누구든 같은 환경을 만들 수 있어요!

.env = 비밀번호 금고

API 키 같은 민감한 정보를 안전하게 보관하는 파일이에요.

API_KEY=abcdefg12345

코드에서는 process.env.API_KEY로 가져와요. 코드 파일에 비밀번호를 직접 쓰면 GitHub에 올릴 때 전 세계에 공개되니까, 반드시 .env 파일에 따로 보관해야 해요!

.gitignore: Git에 올리면 안 되는 것들

프로젝트 루트에 .gitignore 파일을 만들고 이 2줄을 적어두세요.

node_modules/   # 재료 보관함 (용량 크고, npm install로 재설치 가능)
.env            # 비밀번호 금고 (API 키 유출 위험!)

중요: 비밀번호를 코드에 직접 쓰면 GitHub에 push할 때 전 세계에 공개돼요! 반드시 .env에 넣고, .gitignore에 등록하세요.

1 데이터 수집 — RSS로 뉴스 가져오기

크롤링 vs RSS

뉴스를 가져오는 방법은 크게 두 가지예요.

크롤링 = "몰래 가져오기" RSS = "공식 전단지"
웹페이지를 직접 긁어옴 사이트가 공식으로 제공하는 피드
법적 문제 가능성 있음 안전하고 합법적

우리는 RSS를 써요. 구글 뉴스가 공식으로 제공하는 전단지를 가져오는 거예요.

원석 vs 보석: 인터넷의 데이터는 정제되지 않은 원석(Raw Data)이에요. 이 원석에서 필요한 보석(제목, 링크)만 골라내는 작업을 파싱(Parsing)이라고 해요. 생선에서 가시를 발라내고 살코기만 남기는 것과 같아요.

원석(RSS) → 파싱(가시 발라내기) → 보석(제목, 링크, 날짜)

프로젝트 세팅

mkdir my-news-bot && cd my-news-bot
npm init -y
npm install rss-parser

Node.js란? 브라우저 없이 JavaScript를 실행할 수 있게 해주는 환경이에요. npm install은 섹션 3에서 배운 "레시피북"이에요 — 필요한 재료(rss-parser)를 설치하는 거예요.

AI에게 코드 요청하기

"rss-parser 라이브러리로 구글 뉴스 RSS에서 'AI' 키워드 최신 기사 3개의 제목과 링크를 출력하는 index.js 파일을 만들어줘. 한글 주석 달아줘."

프롬프트 분석 — 왜 이렇게 쓸까요?
• "rss-parser 라이브러리로" → 어떤 도구를 쓸지 지정 (AI가 다른 걸 쓰는 걸 방지)
• "최신 기사 3개" → 수량을 명시 (안 하면 100개를 가져올 수도 있어요)
• "제목과 링크를" → 필요한 데이터를 구체적으로 지정
• "index.js 파일을 만들어줘" → 파일명까지 지정하면 헷갈릴 일이 없어요
• "한글 주석" → 나중에 코드를 봤을 때 이해하기 쉽게

Google News RSS URL

https://news.google.com/rss/search?q=인공지능&hl=ko&gl=KR&ceid=KR:ko

q=검색어 부분을 바꾸면 원하는 키워드의 뉴스를 가져올 수 있어요. 파싱(Parsing)이란 이 RSS 데이터에서 제목, 링크 같은 "보석"만 골라내는 거예요.

AI가 만들어준 코드 (핵심 부분)

const Parser = require('rss-parser');
const parser = new Parser();

// 구글 뉴스에서 'AI' 관련 기사 가져오기
const feed = await parser.parseURL('RSS_URL');
feed.items.slice(0, 3).forEach(item => {
  console.log(`[제목] ${item.title}`);
  console.log(`[링크] ${item.link}`);
});

코드를 다 이해할 필요는 없어요. 핵심만 보면: slice(0, 3)이 "3개만 가져와"이고, item.title이 "제목을 꺼내줘"예요.

슬랙으로 보내면 폰에서 바로 확인할 수 있어요. 이때 쓰는 게 아까 배운 Webhook(초인종)이에요.

2 슬랙 전송 — Webhook으로 메시지 보내기

Webhook = 초인종, 다시 한번

슬랙에 "비밀 우체통 주소"를 하나 만들어요. 그 주소로 데이터를 보내면 슬랙 채널에 메시지가 뜨는 거예요.

슬랙 앱 만들기 (6단계)

  1. Slack API 사이트 접속 (api.slack.com)
  2. "Create New App" → "From scratch" 선택
  3. 앱 이름 지정 (예: Morning News Bot) + 워크스페이스 선택
  4. "Incoming Webhooks" 메뉴 클릭
  5. "Activate Incoming Webhooks" 스위치 켜기
  6. "Add New Webhook to Workspace" → 채널 선택 → URL 복사

주의: 이 Webhook URL이 유출되면 아무나 내 채널에 메시지를 보낼 수 있어요! 절대 코드에 직접 넣지 말고, 섹션 3에서 배운 .env 파일(비밀번호 금고)에 보관하세요.

추가 설치

npm install axios dotenv

AI에게 코드 요청하기

"기존 index.js에 슬랙 전송 기능을 추가해줘.
- axios로 슬랙 Webhook URL에 POST 요청을 보내는 sendToSlack 함수를 만들어줘.
- Webhook 주소는 .env 파일의 SLACK_WEBHOOK_URL에서 가져와.
- 뉴스 제목 3개를 하나의 메시지로 합쳐서 보내줘."

프롬프트 분석 — 왜 이렇게 쓸까요?
• "기존 index.js에 추가해줘" → 새 파일을 만들지 말고 기존 코드에 합치라는 뜻
• "sendToSlack 함수를 만들어줘" → 함수 이름까지 지정하면 코드가 깔끔해요
• ".env 파일에서 가져와" → 보안 패턴을 명시적으로 요청
• "하나의 메시지로 합쳐서" → 안 하면 3개를 따로따로 보낼 수도 있어요

Node.js가 JSON 편지를 Webhook URL(비밀 통로)로 보내면, Slack이 받아요

POST 방식이란?

HTTP 요청에는 두 가지가 있어요. GET = "정보 줘" (가져오기), POST = "이거 받아" (보내기). 슬랙에 메시지를 보내는 거니까 POST를 써요.

핵심 코드: sendToSlack 함수

async function sendToSlack(message) {
  // .env에서 비밀 주소 가져오기
  const url = process.env.SLACK_WEBHOOK_URL;
  try {
    // 슬랙으로 메시지 쏘기 (POST 방식)
    await axios.post(url, { text: message });
    console.log('슬랙 전송 완료!');
  } catch (error) {
    console.error('배달 실패:', error);
  }
}

이 코드에서 가장 중요한 한 줄: axios.post(url, { text: message }) — "이 주소로 이 메시지를 보내줘"라는 뜻이에요.

실행해보기

node index.js

→ 슬랙 채널에 뉴스 요약 메시지가 도착하면 STEP 2 성공!

뉴스를 모아서 슬랙으로 보내는 것까지 됐어요! 하지만 아직 한 가지 남았어요...

지금은 node index.js를 직접 실행해야 뉴스가 보내져요. 매일 아침 일어나서 터미널을 열고 명령어를 치는 건... 자동화가 아니죠?

진짜 자동화란, 내가 아무것도 안 해도 알아서 실행되는 거예요. 이때 쓰는 게 아까 배운 Cron(알람 시계)이에요. 그런데 내 컴퓨터가 꺼져 있으면? GitHub가 대신 실행해줘요!

3 24/7 자동화 — GitHub Actions로 매일 자동 실행

GitHub Actions = "깃허브가 빌려주는 무료 컴퓨터"예요. 매달 무료 2,000분까지 사용할 수 있어요.

서버리스(Serverless) 자동화란? 원래 자동화하려면 24시간 켜져 있는 서버가 필요해요. 근데 GitHub Actions가 대신 컴퓨터를 빌려주니까, 우리는 서버를 신경 쓸 필요 없어요.

AI에게 워크플로우 요청하기

"GitHub Actions로 매일 한국 시간 아침 9시에 index.js를 자동 실행하는 워크플로우 파일을 만들어줘.
- .github/workflows/daily.yml 경로에 만들어줘.
- Node.js 18 버전을 사용해.
- npm install 후 node index.js를 실행해.
- SLACK_WEBHOOK_URL은 GitHub Secrets에서 가져와."

프롬프트 분석 — 왜 이렇게 쓸까요?
• "한국 시간 아침 9시" → AI가 알아서 UTC로 변환해줘요 (한국 9시 = UTC 0시)
• ".github/workflows/daily.yml 경로" → 파일 위치까지 지정하면 실수가 줄어요
• "Node.js 18 버전" → 버전을 명시해야 호환성 문제가 없어요
• "GitHub Secrets에서 가져와" → .env 파일은 GitHub에 안 올라가니까, Secrets를 써야 해요

시간 주의! (UTC vs KST)

GitHub 컴퓨터는 영국 시간(UTC)을 써요. 한국(KST)은 +9시간이에요. AI에게 "한국 시간"이라고 말하면 알아서 변환해주지만, 알아두면 좋아요.

한국 시간 (KST) UTC Cron 설정
오전 9시 0시 cron: '0 0 * * *'
오후 2시 5시 cron: '0 5 * * *'
오후 6시 9시 cron: '0 9 * * *'

비밀값 등록하기

.env 파일은 GitHub에 올라가지 않으니까, Webhook URL을 GitHub Secrets에 따로 등록해야 해요.

  1. GitHub 저장소의 Settings 클릭
  2. Secrets and variables → Actions 클릭
  3. New repository secret 버튼 클릭
  4. Name에 SLACK_WEBHOOK_URL 입력
  5. Secret에 실제 주소 붙여넣기 → Add secret

Cron(시간 트리거) → Runner(가상 컴퓨터) → Secrets(비밀 저장소) → 실행(Node.js)
